# Paige's Corner spruce-up — 2026-10-13 (branch `paige-spruce-2026-10-13`)

Visual polish, Kitchen Corner features, and a full SEO pass. Sunflower identity,
private Family Zone behavior, and monetization setup are unchanged.

## What changed

**SEO**
- `frontend/index.html`: duplicate AdSense meta + script tags removed (exactly one
  of each remains; AdSense itself untouched). Added meta description, canonical,
  robots, theme-color, and full Open Graph / Twitter cards pointing at a
  self-hosted `/og-image.jpg` (1200×630 frame from the site's own sunflower
  opener video).
- Per-page titles + descriptions via `frontend/src/hooks/usePageMeta.js` on Home,
  Blog, Mental Health, Healthy Food, Paige's Kitchen, and Paige's Shorts.
- `public/sitemap.xml` rewritten with the real routes (`/home`, `/blog`,
  `/kitchen`, `/mental`, `/healthy`, `/shorts`, `/contact.html`,
  `/privacy.html`, `/terms.html`). The old sitemap listed `/about`,
  `/privacy-policy`, and `/terms`, which do not exist.
- `public/robots.txt`: public content fully allowed; private family areas
  (`/login`, `/family`, `/game/`, `/warp`, `/api/`) disallowed for indexing.

**Features**
- Recipe cards (`RecipeCard.jsx`): the previously dead buttons now work —
  "Printable recipe" prints just the card (print stylesheet in `index.css`),
  "Share kindness" copies the recipe to the clipboard with feedback. New
  servings scaler (½×/1×/2×/3×) rescales ingredient quantities, including
  fractions, mixed numbers, unicode fractions, and ranges. Images lazy-load.
- Paige's Kitchen (`PaigesKitchen.jsx`): new "whole recipe shelf" — every
  recipe (not just the latest) with a live search filter. Admin panel untouched.
- Blog cards show the post excerpt and author byline.
- `getBlog()` in `frontend/src/lib/api.js` now reads the Worker's real public
  rail `/api/public/blog` and adapts its shape — the blog pages finally render
  the actual published posts ("Kitchen Corner", "Garden Notes") instead of
  empty states. Read-only; failures fall back to the old empty states.
- New warm `Footer` (site links + Privacy/Terms/Contact) on all public pages.
- Hero gained "Visit Paige's Kitchen" / "Read the journal" calls to action.

**Privacy / performance**
- Intro splash and the home "Beautiful Moments" section no longer stream video
  from third parties (coverr.co / mixkit.co). Both now use the self-hosted
  `/SunFlower_opener.mp4`. The intro also has a visible "Enter Paige's Corner"
  button instead of only an 8-second auto-advance.
- Accessibility: `:focus-visible` rings, `prefers-reduced-motion` handling,
  aria labels on navigation, descriptive image alt text.

## Verified

- `npm run build` passes (Vite, 1,766 modules).
- Real-browser (Chromium/CDP) run of the production build: 30 assertions
  covering titles/meta, hero CTAs, footer, single AdSense tag, local-only
  video, live blog posts rendering, the recipe scaler math
  (1½ cups → 3 cups at 2×, 2–3 tbsp → 4–6, ½ cup → 1), shelf search,
  and mobile layout (390px, no horizontal overflow) — all pass.
  (Two early "failures" were test artifacts: the 1× baseline correctly shows
  ingredients exactly as typed, and the byline check was case-sensitive
  against a CSS-uppercased element — visually confirmed "BY PAIGE".)

## Deploy

Per repo setup, production is the Cloudflare Worker `paigeswaincom`
(`wrangler.toml`, assets = `./dist`, Git integration on push to `main`).
To ship: merge `paige-spruce-2026-10-13` into `main` and push, or run
`npm run deploy` from a machine with Wrangler auth. NOT deployed by this change.

## Known pre-existing issue (not fixed here — needs its own decision)

The deployed frontend calls legacy endpoints (`/api/blog`, `/api/recipes`,
`/api/journal`, `/api/joke`, `/api/compliment`, `/api/login`, `/api/session`,
`/api/leaderboard`, `/api/message`, `/api/spin`) that the production Worker
does **not** implement — it serves `/api/public/*`, `/api/auth/*`,
`/api/dashboard/*`, `/api/family/*` and 404s everything else under `/api/`
(verified live 2026-10-13). Consequences in production today: recipes,
journal, dad-joke, and compliment rails show their empty states, and the
name-based Family Login cannot complete against `/api/login`. This spruce-up
bridged the one read-only public rail that exists (blog). Wiring the
remaining rails means either adding Worker endpoints for recipes/journal or
re-pointing the frontend at the family-content APIs — a bigger change that
touches the private area's contracts, so it was left for a separate,
deliberate pass.
